1. როგორ მუშაობს საიტი

  1. სტუმარი საიტზე ირჩევს კერძებს და აჭერს „WhatsApp-ით გაგზავნას“. შეკვეთა მზა ტექსტად მოდის კაფის WhatsApp ნომერზე. ონლაინ გადახდა საიტზე არ ხდება.
  2. მენიუ, ფასები, ფოტოები და პარამეტრები ინახება GitHub-ზე, ფაილებში content/menu.json და content/settings.json, ფოტოები — content/photos/-ში.

  4. ყოველი „Save“ GitHub-ზე ქმნის ჩანაწერს (commit). GitHub ავტომატურად ამოწმებს მონაცემებს და დაახლოებით 2 წუთში აქვეყნებს განახლებულ საიტს.

2. შესვლა და თანამშრომლების მოწვევა

მფლობელი (GitHub ანგარიშით)

  1. გახსენით app.pagescms.org და დააჭირეთ Sign in with GitHub.
  2. პირველად: დაუშვით Pages CMS აპლიკაცია რეპოზიტორიაზე frossigneux/cafe (შეიძლება მხოლოდ ამ ერთზე).
  3. აირჩიეთ პროექტი cafe. მარცხნივ ჩანს: მენიუ · Menu, პარამეტრები · Settings, Media.

თანამშრომლები (GitHub-ის გარეშე)

  1. მფლობელი: მარცხნივ Admin → Collaborators → Invite a collaborator, შეიყვანეთ თანამშრომლის ელფოსტა.
  2. თანამშრომელი იღებს წერილს ბმულით. ბმულით შედის Pages CMS-ში, პაროლი არ სჭირდება.

5. შენახვის შემდეგ

  • საიტი განახლდება დაახლოებით 2 წუთში. შეამოწმეთ ტელეფონით (საჭიროების შემთხვევაში გვერდი განაახლეთ).

  • რამდენიმე ადამიანი ერთდროულად ნუ ცვლის ერთსა და იმავე გვერდს.

7. ტექნიკური სპეციალისტისთვის

სტატიკური საიტი Astro 6-ით (Node 22), სერვერისა და მონაცემთა ბაზის გარეშე. ყოველი push-ის შემდეგ main-ზე .github/workflows/deploy.yml აწყობს საიტს და აქვეყნებს GitHub Pages-ზე. რეპოზიტორია: github.com/frossigneux/cafe.

ფაილიდანიშნულება
content/menu.json, content/settings.jsonკაფის ყველა მონაცემი. აწყობისას მოწმდება (src/data/*.ts); შეცდომისას აწყობა ჩერდება გასაგები შეტყობინებით.
content/photos/კერძების და გალერეის ფოტოები, მითითება: /photos/x.jpg.
.pages.ymlPages CMS-ის ფორმების აღწერა (ორენოვანი წარწერები).
content/README.mdJSON-ის პირდაპირ GitHub-ზე რედაქტირების ინსტრუქცია.
src/i18n.tsინტერფეისის ტექსტები (ka / en / ru) და WhatsApp შეტყობინების ტექსტი.
src/components/OrderPage.astro, src/scripts/order.ts, src/styles/global.cssგვერდი, კალათა, WhatsApp-ის ლოგიკა, სტილები.
scripts/make-og.pyქმნის public/og.jpg-ს (გაზიარების სურათი) სახელიდან და გალერეის პირველი სურათიდან.
docs/guide/ეს გზამკვლევი (HTML, PDF, სურათები).
DESIGN.md, PRODUCT.mdდიზაინის სისტემა და პროდუქტის გადაწყვეტილებები.

ლოკალური მუშაობა

git clone git@github.com:frossigneux/cafe.git && cd cafe
npm ci
npm run dev      # http://localhost:4321
npm run build    # იგივე შემოწმება, რაც გამოქვეყნებისას

ყოველთვის ჯერ git pull: Pages CMS-ში შეტანილი ცვლილებები commit-ებია main-ზე.

Pages CMS-ის თავისებურებები

  • Pages CMS ინახავს მხოლოდ .pages.yml-ში აღწერილ ველებს. ახალი JSON ველი იქაც უნდა დაემატოს, თორემ შემდეგ შენახვისას წაიშლება.
  • ცარიელი ველები ინახება როგორც "" ან null; საიტი მათ არარსებულად თვლის.
  • .pages.yml-ის შეცვლის შემდეგ შეამოწმეთ ფორმა. თუ ძველი ფორმა ჩანს, გააკეთეთ კიდევ ერთი მცირე ცვლილება .pages.yml-ში (კომენტარი) და push: Pages CMS ქეშს GitHub-ის შეტყობინებით ანახლებს.

8. დომენი Worldbus.ge-ზე

საიტი ახლა არის frossigneux.github.io/cafe/. საკუთარი .ge დომენი (მაგ. maifamily.ge) შეიძლება დარეგისტრირდეს worldbus.ge-ზე და დაუკავშირდეს GitHub Pages-ს.

  1. დაარეგისტრირეთ დომენი worldbus.ge-ზე (Domains). ანგარიშის ელფოსტა: . განაახლეთ ყოველწლიურად, თორემ მისამართი აღარ იმუშავებს.
  2. Worldbus-ის DNS პანელში (სტანდარტული სერვერები ns1.worldbus.ge / ns2.worldbus.ge) შექმენით:

  3. GitHub-ზე: რეპოზიტორია Settings → Pages → Custom domain, შეიყვანეთ დომენი, შეინახეთ, დაელოდეთ DNS შემოწმებას და ჩართეთ Enforce HTTPS. CNAME ფაილი საჭირო არ არის.
